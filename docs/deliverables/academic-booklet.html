บทคัดย่อ

โครงงานนี้เป็นการพัฒนาระบบ W10 Dashboard ซึ่งเป็นแดชบอร์ดสำหรับติดตามงานซ่อมบำรุงและจัดซื้อจัดจ้างของกองบำรุงรักษาโรงไฟฟ้าแม่เมาะ หน่วยที่ 10 (W10) การไฟฟ้าฝ่ายผลิตแห่งประเทศไทย (กฟผ.)

ปัญหา: เดิมหน่วยงาน W10 จัดเก็บข้อมูลงานซ่อมบำรุง การจัดซื้อจัดจ้าง คลังอะไหล่ และการทำงานล่วงเวลาไว้ใน Google Sheets หลายไฟล์ ทำให้การตรวจสอบสถานะงานต้องเปิดดูหลายชีตพร้อมกัน ข้อมูลกระจัดกระจาย ไม่สามารถดูภาพรวมได้อย่างรวดเร็ว และไม่มีระบบจัดการใบสั่งซ่อม (Shop Order) แบบ CRUD ที่รองรับการแนบไฟล์

แนวทางแก้ไข: พัฒนาเว็บแอปพลิเคชันด้วย Next.js 16 ร่วมกับ React 19 และ TypeScript โดยเชื่อมต่อกับ Google Sheets API เพื่อดึงข้อมูลแบบ real-time แสดงผลในรูปแบบแดชบอร์ดที่มีกราฟ ตาราง และการ์ดสรุป พร้อมระบบ Shop Order ที่รองรับ CRUD, การแนบไฟล์ผ่าน Google Drive API ด้วย OAuth 2.0 และ resumable upload

ผลลัพธ์: ระบบประกอบด้วย 7 หน้าหลัก ได้แก่ หน้าหลัก (Work Order Dashboard), หน้าจัดซื้อจัดจ้าง (Purchasing), หน้าจัดซื้อจัดจ้างรวม (Purchasing All), หน้าคลังอะไหล่ BEML, หน้าสรุป OT ลูกจ้าง, หน้าสรุป OT พนักงาน และหน้า Shop Order ระบบผ่านการทดสอบ Unit Test จำนวน 270 tests จาก 25 ไฟล์ ทดสอบ TypeScript strict mode, production build สำเร็จ และ deploy บน Vercel เรียบร้อย

ประโยชน์: ช่วยให้เจ้าหน้าที่ W10 ตรวจสอบสถานะงานซ่อมบำรุง ติดตามการจัดซื้อจัดจ้าง จัดการคลังอะไหล่ และดูข้อมูล OT ได้จากจุดเดียว ลดเวลาในการค้นหาข้อมูลและเพิ่มประสิทธิภาพการทำงานของหน่วยงาน

1.1 ความเป็นมาและความสำคัญของปัญหา

การไฟฟ้าฝ่ายผลิตแห่งประเทศไทย (กฟผ.) เป็นรัฐวิสาหกิจที่รับผิดชอบการผลิตไฟฟ้าของประเทศไทย โรงไฟฟ้าแม่เมาะ จังหวัดลำปาง เป็นหนึ่งในโรงไฟฟ้าหลักที่มีกำลังการผลิตสูง โดยกองบำรุงรักษาโรงไฟฟ้าแม่เมาะ หน่วยที่ 10 (W10) มีหน้าที่ดูแลซ่อมบำรุงอุปกรณ์ต่าง ๆ ของโรงไฟฟ้า

ในการปฏิบัติงานประจำวัน เจ้าหน้าที่ W10 จำเป็นต้องติดตามข้อมูลหลายด้านพร้อมกัน ได้แก่ สถานะใบสั่งงาน (Work Order), ความคืบหน้าการจัดซื้อจัดจ้าง, สต็อกอะไหล่ BEML, ข้อมูลการทำงานล่วงเวลา (OT) และใบสั่งซ่อม (Shop Order) ข้อมูลเหล่านี้ถูกจัดเก็บใน Google Sheets หลายไฟล์ ทำให้การตรวจสอบข้อมูลต้องเปิดหลายหน้าต่าง ใช้เวลานาน และมีโอกาสผิดพลาดสูง

นอกจากนี้ การจัดการใบสั่งซ่อม (Shop Order) ยังเป็นกระบวนการที่ต้องทำด้วยมือ ไม่มีระบบ CRUD ที่เป็นระบบ ไม่สามารถแนบไฟล์เอกสารได้สะดวก และไม่มีภาพรวมของงานที่กำลังดำเนินการ

ดังนั้นผู้จัดทำจึงได้พัฒนา W10 Dashboard เพื่อรวบรวมข้อมูลจาก Google Sheets มาแสดงผลในรูปแบบแดชบอร์ดที่เข้าใจง่าย พร้อมระบบจัดการ Shop Order แบบครบวงจร

1.2 วัตถุประสงค์ของโครงงาน

  1. เพื่อพัฒนาระบบแดชบอร์ดที่รวบรวมข้อมูลงานซ่อมบำรุง การจัดซื้อจัดจ้าง คลังอะไหล่ และ OT ไว้ในที่เดียว
  2. เพื่อพัฒนาระบบจัดการ Shop Order ที่รองรับ CRUD และการแนบไฟล์
  3. เพื่อลดเวลาในการค้นหาและตรวจสอบข้อมูลของเจ้าหน้าที่ W10
  4. เพื่อนำเสนอข้อมูลในรูปแบบกราฟและภาพรวมที่เข้าใจง่าย
  5. เพื่อศึกษาและฝึกทักษะการพัฒนาเว็บแอปพลิเคชันด้วยเทคโนโลยีสมัยใหม่

1.3 ขอบเขตของโครงงาน

  1. ระบบเป็นเว็บแอปพลิเคชันที่ทำงานบนเบราว์เซอร์ รองรับทั้ง Desktop และ Mobile
  2. ข้อมูลทั้งหมดอ่านจาก Google Sheets เป็นแหล่งข้อมูลหลัก (Source of Truth)
  3. ระบบ Shop Order รองรับ CRUD (สร้าง อ่าน แก้ไข ลบ) พร้อมแนบไฟล์ JPEG, PNG, WebP และ PDF ขนาดไม่เกิน 10 MB
  4. ไฟล์แนบจัดเก็บบน Google Drive ผ่าน OAuth 2.0
  5. ระบบ deploy บน Vercel Platform
  6. ระบบไม่มีหน้า Login — ใช้การควบคุมด้วย URL และ WAF
  7. ครอบคลุม 7 หน้าหลัก: Dashboard, Purchasing, Purchasing All, BEML Inventory, OT Summary, OT Employee, Shop Order

1.4 ประโยชน์ที่คาดว่าจะได้รับ

  1. เจ้าหน้าที่ W10 สามารถดูภาพรวมงานซ่อมบำรุงได้จากหน้าจอเดียว
  2. ลดเวลาในการค้นหาข้อมูลจากหลาย Google Sheets
  3. มีระบบจัดการ Shop Order ที่เป็นระเบียบ รองรับการแนบเอกสาร
  4. ผู้บริหารสามารถติดตามสถานะงานและค่าใช้จ่ายได้สะดวก
  5. ผู้จัดทำได้เรียนรู้เทคโนโลยี Next.js, React, TypeScript, Google APIs และ OAuth 2.0

2.1 Next.js และ React

React เป็น JavaScript library สำหรับสร้าง User Interface พัฒนาโดย Meta (Facebook) ใช้แนวคิด Component-based ทำให้สามารถแบ่งหน้าจอออกเป็นชิ้นส่วนย่อย ๆ ที่จัดการได้ง่าย โครงงานนี้ใช้ React เวอร์ชัน 19.2.4

Next.js เป็น React Framework ที่เพิ่มความสามารถ Server-Side Rendering (SSR), Static Site Generation (SSG), API Routes และ App Router ทำให้การพัฒนาเว็บแอปพลิเคชันมีประสิทธิภาพสูง โครงงานนี้ใช้ Next.js เวอร์ชัน 16.2.12

2.2 TypeScript

TypeScript เป็นภาษาโปรแกรมที่ต่อยอดจาก JavaScript โดยเพิ่มระบบ Type ช่วยตรวจจับข้อผิดพลาดตั้งแต่ขั้นตอนการเขียนโค้ด ลดบั๊กที่เกิดในขั้นตอน runtime โครงงานนี้ใช้ TypeScript ในโหมด strict เพื่อความปลอดภัยสูงสุด

2.3 Google Sheets API

Google Sheets API เป็น API ที่ให้แอปพลิเคชันอ่านและเขียนข้อมูลใน Google Sheets ได้โดยตรง โครงงานนี้ใช้ Service Account เพื่อเข้าถึง Spreadsheet โดยไม่ต้องให้ผู้ใช้ login ข้อมูลที่อ่านได้แก่ สถานะ Work Order, ข้อมูลจัดซื้อ, คลังอะไหล่ BEML, ข้อมูล OT และ Shop Order

2.4 Google Drive API และ OAuth 2.0

Google Drive API ใช้สำหรับจัดเก็บไฟล์แนบของ Shop Order โครงงานนี้ใช้ OAuth 2.0 ด้วย scope drive.file ซึ่งจำกัดสิทธิ์ให้จัดการเฉพาะไฟล์ที่แอปสร้างขึ้นเท่านั้น การอัปโหลดใช้ Resumable Upload Protocol เพื่อรองรับไฟล์ขนาดใหญ่ได้อย่างเสถียร

2.5 Vercel Platform

Vercel เป็นแพลตฟอร์ม Cloud สำหรับ deploy เว็บแอปพลิเคชัน โดยเฉพาะ Next.js รองรับ Serverless Functions, Edge Network และ Cron Jobs โครงงานนี้ใช้ Vercel สำหรับ production deployment และ cron job สำหรับ cleanup ไฟล์หมดอายุ

2.6 Tailwind CSS

3.1 ข้อมูลทั่วไปของ กฟผ.

การไฟฟ้าฝ่ายผลิตแห่งประเทศไทย (กฟผ.) หรือ Electricity Generating Authority of Thailand (EGAT) เป็นรัฐวิสาหกิจด้านพลังงานภายใต้การกำกับดูแลของกระทรวงพลังงาน ก่อตั้งเมื่อวันที่ 1 พฤษภาคม พ.ศ. 2512 มีภารกิจหลักคือผลิตไฟฟ้า จัดหาเชื้อเพลิง ดำเนินธุรกิจเกี่ยวเนื่อง และดูแลระบบส่งไฟฟ้าให้มีความมั่นคง เชื่อถือได้ ในราคาที่เหมาะสม

3.2 โรงไฟฟ้าแม่เมาะ

โรงไฟฟ้าแม่เมาะ ตั้งอยู่ที่อำเภอแม่เมาะ จังหวัดลำปาง เป็นโรงไฟฟ้าพลังงานความร้อนที่ใช้ถ่านหินลิกไนต์เป็นเชื้อเพลิงหลัก มีกำลังการผลิตรวมหลายพันเมกะวัตต์ เป็นหนึ่งในโรงไฟฟ้าหลักที่สำคัญของประเทศไทย

3.3 กองบำรุงรักษา W10

กองบำรุงรักษาโรงไฟฟ้าแม่เมาะ หน่วยที่ 10 (W10) เป็นหน่วยงานที่รับผิดชอบการซ่อมบำรุงอุปกรณ์ต่าง ๆ ของโรงไฟฟ้า แบ่งกลุ่มงานย่อยเป็น 4 กลุ่ม ได้แก่ W11, W12, W13 และ W14 แต่ละกลุ่มรับผิดชอบอุปกรณ์ที่แตกต่างกัน

งานหลักของ W10 ประกอบด้วย:

  • การซ่อมบำรุงเชิงแก้ไข (Corrective Maintenance)

5.7 ความปลอดภัยและความทนทาน

ระบบ Shop Order แยกความลับระหว่าง Sheets กับ Drive อย่างชัดเจน:

  • Sheets ใช้ Service Account ด้วย scope spreadsheets เท่านั้น
  • Drive ใช้ OAuth ด้วย scope drive.file เท่านั้น
  • Client ไม่ได้รับ client secret, refresh token หรือ private key
พื้นที่ควบคุมมาตรการ
Input validationJSON content type, same-origin check, 6-digit order, strict date, MIME/extension/size/signature
Secret handlingenv-only; setup utility ไม่เขียน .env และไม่พิมพ์ access token
URL allowlistupload session เฉพาะ googleapis.com; thumbnail เฉพาะ googleusercontent.com
Attachment ownershipตรวจ file id, parent folder, appProperties, order number, metadata
Traffic controlระบบเป็น public-by-link จึงต้องใช้ WAF rate limit 30 requests/IP/10 นาที
Cleanup authBearer secret ตรวจด้วย timingSafeEqual

Failure Modes ที่รองรับ

  • Google Drive reauth/quota/folder/access/unavailable → ถูก map เป็น safe error code ภาษาไทย
  • อัปโหลดไฟล์ล้มเหลว → บันทึก order สำเร็จ → UI เปิดทางให้เพิ่มไฟล์อีกครั้ง
  • Sheet append/update/clear ล้มเหลวหลัง finalize → restore pending metadata + ลบ permission ใหม่
  • Cleanup เป็น idempotent: ไม่พบไฟล์หรือถูกย้าย Trash แล้ว → ไม่นับเป็น failure
  • Thumbnail ใช้ authenticated proxy + fallback เมื่อไม่พบรูปย่อ

สรุปผลและข้อเสนอแนะ

7.1 สรุปผลการดำเนินงาน

ผู้จัดทำได้พัฒนาระบบ W10 Dashboard สำเร็จตามวัตถุประสงค์ที่ตั้งไว้ โดยระบบประกอบด้วย 7 หน้าหลักที่ครอบคลุมการทำงานของหน่วยงาน W10 ทั้งหมด ได้แก่:

  1. หน้าหลัก (Dashboard) — แสดงภาพรวม Work Order, สถานะงาน, อุปกรณ์ และ Load Factor แยกตามกลุ่ม W11-W14
  2. หน้าจัดซื้อจัดจ้าง — แสดงสรุปหมวดการซื้อ/จ้าง พร้อมกราฟ 3D และตารางค้นหาได้
  3. หน้าคลังอะไหล่ BEML — แสดง stock map, health ring และรายละเอียดอะไหล่
  4. หน้า OT — แยกพนักงานและลูกจ้างพร้อมข้อมูล ETAS scan
  5. หน้า Shop Order — ระบบ CRUD เต็มรูปแบบพร้อมแนบไฟล์ผ่าน Google Drive

ระบบผ่านการทดสอบ Unit Test 270 tests สำเร็จทั้งหมด, TypeScript strict mode ไม่มี error, production build สำเร็จ และ deploy บน Vercel เรียบร้อย สามารถเข้าถึงได้ที่ https://w10-jet.vercel.app/

7.2 ปัญหาและอุปสรรค

ระดับข้อค้นพบผลกระทบ/คำแนะนำ
สูงPublic mutation API ไม่มี loginผู้ที่เข้าถึง URL เรียก CRUD ได้; ต้องควบคุม URL/WAF หรือวาง auth
สูงDashboard API คืน debugInfo 10 แถวแรกอาจเผยข้อมูลชีดที่ไม่ต้องการ; ควรเอาออกจาก response
กลางFull lint ไม่ผ่าน 144 errors/10 warningsเพิ่มความเสี่ยง regression; ควรทำให้ CI gate ผ่าน lint
กลางUI shell migrate เพียง /ot-employeeเป้าหมาย 7 routes อัปเดต shell ยังไม่ครบ
ต่ำHard-coded sheet IDs/rangesเปลี่ยน tab/column ต้องแก้ code และเพิ่ม test

7.3 ข้อเสนอแนะ

  1. แก้หรือเอา debugInfo ออกจาก public response ของ legacy API
  2. กำหนด access model ให้ชัด: ถ้ายัง public ให้บังคับ WAF/URL governance; ถ้ามีข้อมูลลับให้เพิ่ม authentication
  3. จัดทำ env contract กลาง แยกกลุ่ม Dashboard, OT, BEML และ Shop Order
  4. ทำ lint baseline cleanup เป็นงานแยก
  5. ทำ browser verification matrix ให้ครบทุก route/viewport
  6. เดินหน้า UI shell migration ตามแผน โดยรักษา route data behavior เดิม
